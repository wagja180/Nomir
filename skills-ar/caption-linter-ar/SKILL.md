# فاحص الكابشن (عربي)

فحص آلي لمسودة كابشن — ليس إعادة كتابة من الصفر (استخدم `caption-writer-ar` لذلك، و`humanizer-ar` إن كانت المسودة تبدو كأن الذكاء الاصطناعي كتبها). مهمة هذه المهارة هي رصد مشاكل محددة وقابلة للإصلاح: هوك مدفون، دعوة فعل غائبة أو مضخّمة، إفراط في الهاشتاغات، عبارات مستهلكة، ادعاءات غير مدعومة، تنسيق سيء.

## متى تُستخدم
- كابشن موجود فعلًا (كتبه المستخدم أو `caption-writer-ar`) ويحتاج فحصًا قبل النشر.
- المستخدم يسأل "هل هذا الكابشن جيد؟" أو "ما المشكلة في هذا الكابشن؟"

## خطوات العمل

1. اقرأ `reference/lint-rules-ar.md` لمجموعة القواعد الكاملة.
2. طبّق كل قاعدة على الكابشن بالترتيب. لا تتجاهل قاعدة لأن الكابشن "يبدو جيدًا" — افحص كل واحدة بوضوح.
3. لكل قاعدة، اكتب **نجاح** أو **فشل — [حل محدد]**، مع اقتباس الجملة/السطر المخالف عند الحاجة.
4. اختم بحكم عام واحد: **جاهز للنشر**، **يحتاج حلًا واحدًا**، أو **يحتاج إعادة كتابة** — وحدد أي قاعدة/قواعد أدّت لهذا الحكم.
5. إن لم يكن الحكم "جاهز للنشر"، اعرض تطبيق الحلول مباشرة بدل سردها فقط.

## صيغة الإخراج

```
فحص الكابشن: [موضوع المنشور/أول كلمات]

1. سطر الهوك الأول: نجاح/فشل — [ملاحظة]
2. تناسب الطول مع الهدف: نجاح/فشل — [ملاحظة]
3. دعوة فعل واحدة واضحة: نجاح/فشل — [ملاحظة]
4. سهولة القراءة والتنسيق: نجاح/فشل — [ملاحظة]
5. الهاشتاغات: نجاح/فشل — [ملاحظة]
6. العبارات الممنوعة/المستهلكة: نجاح/فشل — [ملاحظة]
7. الادعاءات والالتزام: نجاح/فشل — [ملاحظة]
8. إمكانية الوصول: نجاح/فشل — [ملاحظة]
9. بلا روابط ميتة: نجاح/فشل — [ملاحظة]

الحكم: [جاهز للنشر / يحتاج حلًا واحدًا / يحتاج إعادة كتابة]
```

## ضوابط
- لا تُخفّف إخفاقًا حقيقيًا لمجرد التودد — كابشن بثلاث دعوات فعل متنافسة فشلٌ حتى لو كانت الكتابة جيدة.
- لا تعتبر الكابشن الطويل فشلًا تلقائيًا — الطول فشل فقط إن لم يناسب هدف المنشور (القاعدة 2).
- إذا كان إخفاق الادعاءات غير واضح الحدود، اسأل المستخدم إن كان الادعاء مدعومًا فعليًا قبل اعتباره فشلًا.
